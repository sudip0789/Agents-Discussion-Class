Concept note N5

APIs and databases

In one line: an API is how one program asks another for data. A database’s API returns real records; a search engine returns web pages.

When your agent “looks something up,” it either searches the open web or asks a specific database. The second is slower to set up and narrower, but what comes back is a record that actually exists. This note covers the vocabulary, the databases you used in class, and the rules that keep your keys safe.

The vocabulary

Terms

API (application programming interface)
A set of web addresses a program can call to get data or take an action. It’s a front desk built for programs instead of people.
Endpoint
One of those addresses, such as CourtListener’s citation lookup address, Crossref’s address for looking up a single DOI, or arXiv’s address for searching preprints.
Request and response
Your program asks (the request); the service answers (the response), usually with a status code and the data you asked for.
JSON
JavaScript Object Notation: a structured text format of labeled fields, like "title": "…". Most APIs answer in JSON because programs can read it reliably.
API key or token
A password for a program. It identifies you and is sent with each request. CourtListener expects it as a header: Authorization: Token <your key>.
Rate limit
How many requests you may make in a period. Go over it and requests fail (usually with error 429) until you wait.
Cost
The research databases in this note are free. AI model APIs are billed per token; a paid Claude or ChatGPT plan covers Claude Code or Codex within its usage limits, without a separate API key.

What a request looks like

Here is what one API call looks like. The example uses Crossref, a free database of published articles that needs no key: a program sends one line to Crossref’s endpoint, and Crossref answers with a structured record, or with “not found” if there is no such article. The CourtListener calls your lookup.py makes in lesson 10 work the same way, with case citations instead of article IDs, plus your token.

The real record lists six authors; two are shown. Not every API answers in JSON: arXiv’s API answers in XML (an Atom feed), which a program reads the same way, just with different punctuation.

Search engine vs database

Why it matters

WebSearch is Google, not Westlaw. It finds public web pages; it doesn’t search scholarly or legal databases.

Search engine (WebSearch)Database API
ReturnsPublic web pagesStructured records: title, authors, date, ID
CoverageBroadNarrow: only that database
ReliabilityPages may be wrong, old, or written by another AIThe record exists in the database
AnalogyGoogleWestlaw

A record existing is not the same as a record supporting your point. A database tells you the paper or case is real and gives you its citation. Whether it says what the agent claims is a separate check: in your project, the brief-checker compares every quote with the opinion itself.

Watch out

Most law review articles live on SSRN, which has no public search API. So for legal scholarship, an agent still has to lean on web search, and every result needs extra checking.

Rate limits you’ll actually hit

Free APIs protect themselves by limiting how often you can ask. The limits below are why lookup.py search asks for five results, not fifty.

ServiceLimitWhat it means for you
CourtListener (general API)For authenticated users, by default: 5 requests per minute, 50 per hour, 125 per dayA few dozen lookups in class is fine; a loop over hundreds of cases is not
CourtListener citation lookupUp to 60 valid citations per minute; up to 250 citations per requestVerifying one brief at a time is well within the limit
arXivAsks for about a 3-second delay between repeated callsSpace out searches; don’t hammer it
Semantic ScholarThe unauthenticated pool is shared by everyone and often returns 429; a key starts at 1 request per secondIf it fails, wait and retry, or get a free key
CrossrefOpen to all; adding mailto=you@example.edu to requests puts you in the “polite pool”Identify yourself and you get more reliable service

Sources: CourtListener REST API v4 overview; Citation Lookup API; arXiv API User’s Manual; Semantic Scholar API; Crossref REST API. Limits change; check the docs.

Tip

Keep results small, and if you hit a limit, wait a minute and try again. A 429 error isn’t a bug in your code; it’s the database asking you to slow down.

Keeping keys safe

Treat an API key like a password to an account in your name: anyone holding it can make requests as you.

  1. Store keys in a .env file, never in code. Your project’s lookup.py reads COURTLISTENER_TOKEN from .env and never prints it.
  2. List .env in .gitignore so Git never commits it and it never reaches GitHub. The starter project already does this.
  3. Don’t paste keys into a chat with an agent. Everything you type is sent to the model provider’s servers. Your permission rules also block the agent from reading .env.
  4. If a key leaks, revoke it and create a new one. Deleting the file isn’t enough once it has been shared or committed.

MCP vs API

You’ll hear about MCP, the Model Context Protocol, an open standard for connecting AI apps to outside tools and data. An MCP server packages an API as ready-made tools an agent can call.

Call the API yourself (lookup.py)Use an MCP server
SetupWrite or generate a small programInstall and connect a server
What you can seeEvery line of the code that runsUsually someone else’s code
TrustYou control where your key goesYou trust the server’s author with your access
Best forLearning, and small focused tasksMany tools at once, from a source you trust
Reading an API call like a citation

A request URL has parts, much like a citation has volume, reporter and page. Once you can name them, you can read what any program, including your lookup.py, is asking for.

Example request
https://api.crossref.org/works?query=legal+hallucination&rows=5&mailto=you@example.edu
PartIn the exampleWhat it does
Base addressapi.crossref.orgWhich service you’re calling
Endpoint path/worksWhich kind of record (here, published works)
Parametersquery=…, rows=5, mailto=…The details of your question: search terms, how many results, who you are
Header (not in the URL)Authorization: Token <your key>Sent alongside the request, for services like CourtListener that need a key

Status codes worth knowing

Every response starts with a three-digit status code. Four cover almost everything you’ll see:

CodeMeaningWhat to do
200 OKIt worked; the data is in the responseRead the record
401 / 403Missing, wrong or insufficient keyCheck .env and the header
404 Not FoundNo such recordFor a citation check, this is the signal that a source may be invented
429 Too Many RequestsYou hit the rate limitWait, then retry with fewer requests
