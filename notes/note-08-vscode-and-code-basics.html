Concept note N8

VS Code and code basics

In one line: VS Code puts your files, the agent, and the history side by side, so you can supervise what the agent does.

You don’t need to be a programmer to use VS Code well. You need to know where to look: which files changed, what the agent is about to do, and what the history says. This note is a map of the window and a short glossary of the code you’ll see in it.

The parts of the window

Tip

Supervising an agent is mostly a matter of where your eyes are. Keep the Explorer open to see which files appear, the Claude Code panel to read what it proposes, and Source Control to see exactly what changed.

Files whose names start with a dot (.env, .gitignore, .claude/) are hidden in Finder and File Explorer by default, but VS Code shows them.

How code runs

Code is text that follows a language’s rules. A Python file is run by the Python interpreter, a program that reads it line by line and carries out each instruction. A web page is read and drawn by your browser. When an agent writes code, it writes the same text a person would, and you can open it, read it and edit it.

To run lookup.py yourself, type a command in the terminal. The words after the file name are arguments: they tell the program what to do.

Terminal
python lookup.py verify-citation "5 U.S. 137"

On Windows, if that gives an error, replace python with py. On some Macs it’s python3.

Useful Claude Code commands

CommandWhat it doesWhen to use it
/clearStarts a fresh conversation with an empty contextBefore each new case or test, so old material doesn’t steer the new brief
/contextShows what’s filling the context window, as a colored gridWhen answers get slow, vague or forgetful
/rewind, or Esc twice on an empty promptGoes back to an earlier point: restore the conversation, the code, or bothWhen the agent went the wrong way. It doesn’t undo changes made by terminal commands, so commit often
/brief cases/[file]The command you built: briefs an opinion in cases/, then has the checker check the briefEvery time you want a checked brief

Markdown in 60 seconds

Agent files, skills, CLAUDE.md and your briefs are all Markdown. A few symbols cover almost everything:

You typeYou getWhere you’ll see it
# Project rulesA heading (## for a smaller one)Top of CLAUDE.md; sections of a brief
**bold**boldKey terms in a brief
- itemA bulleted list (1. for numbered)Rules in agent files; skill steps
`code`code, in a fixed-width fontFile names and commands
[link text](https://…)A clickable link that shows link textLinks in the checker’s citations table
--- lines around name:, tools:Frontmatter: a settings block at the very top of a fileThe start of every agent and skill file

To check your formatting, open the preview with Cmd + Shift + V (Mac) or Ctrl + Shift + V (Windows).

Reading code you didn’t write

You won’t write lookup.py by hand, but you are responsible for what it does. Three habits make unfamiliar code readable:

  1. Read the names first. Good code names things plainly: verify_citation, COURTLISTENER_TOKEN. Skim for names before you try to follow any logic.
  2. Read the comments. In Python, anything after # on a line is a note for humans, ignored when the program runs.
  3. Ask for explanations at different levels. In Lesson 10 you asked the agent to explain one line three ways: to a 10-year-old, to a law student, and to an engineer. Comparing the three is a quick test of whether you, and it, really understand the line.

What to look for when reviewing agent-written code

  • Does it read or print anything secret, like the contents of .env?
  • Does it contact any website you didn’t expect?
  • Does it delete, move or overwrite files?
  • When something fails, does it say so plainly, or quietly carry on?
