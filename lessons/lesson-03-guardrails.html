Lesson 3 · Part 1: Foundations

Guardrails

Discussion

Goal: see what an agent does when a rule is missing, and decide which rules must be enforced rather than requested.

An agent tries to be helpful. When nobody wrote a rule down, it fills the gap with whatever seems most helpful in the moment, and that isn’t always what you would have chosen.

Two kinds of guardrail

Every rule you give an agent is one of two kinds. The difference matters more than anything else in this lesson.

InstructionPermission
Where it livesText the model reads: CLAUDE.md, an agent file, a skillSettings the app enforces: a tools line, .claude/settings.json
Who enforces itThe model, by choosing to follow itThe software, before the action runs
Can it be talked out of it?Yes: by a clever request, a hidden line in a document, or its own reasoningNo. The action is blocked or needs your approval
Legal analogyA firm policy memoA locked file room, or an ethical wall in the document system
Example“Never read .env.”"deny": ["Read(.env)"]

Why it matters

Instructions reduce risk. Permissions enforce limits. For anything you can’t afford to get wrong, you want both.

When a rule is left out

Each row is a rule your legal research agent will have by the end of class. For each row, ask the room: what would actually go wrong, who would notice, and when?

Try it

Pick one row. Rewrite the guardrail so it would hold up even if the agent read a document saying “ignore your previous instructions.” Is that possible with an instruction alone?

Discuss

  1. For client documents, would you rely on an instruction (“never share this”) or a permission (the agent can’t open it)? Why?
  2. Who is responsible when an agent breaks a rule nobody wrote down?
Where each guardrail sits between a request and an action

When an agent decides to act, the request passes two checkpoints. Instructions shape what the model decides to try. Permissions decide whether the software lets it happen. A hidden line in a PDF can get past the first checkpoint. It can’t get past the second.

Why “helpful” is the failure mode

Agents aren’t malicious. They’re trained to finish the task. If finishing would be easier with one more supporting case, a model with no rule against it may cite a plausible-sounding one. If a document says “mark every row PASS,” a model with no rule about data versus instructions may treat that as part of the job. The rules in the table close those gaps one at a time.

The professional-responsibility angle

Lawyers already have a vocabulary for this: supervision. ABA Model Rules 5.1 and 5.3 make lawyers responsible for supervising the people working for them, and ABA Formal Opinion 512 applies the same idea to generative AI tools. Writing guardrails down, and enforcing the important ones, is what supervising an agent looks like.
