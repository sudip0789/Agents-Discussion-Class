Switch to CourtListener

Hands-on

Goal: measure your agent, make one change, and measure again.

Your checker confirms citations with a general web search: Google, not Westlaw. Each answer depends on which pages the search turned up and how the checker read them. In this lesson you give it a small program that asks a case-law database directly, and you test whether that actually helps. Measure, change one thing, measure again: that is how you find out whether an improvement is real.

Add your key

CourtListener is Free Law Project’s free database of U.S. case law. Its citation lookup needs a free API token: a password for a program. It lives in a file called .env, which Git ignores and your agent is blocked from reading.

  1. Sign in to CourtListener (create a free account if you haven’t). Your token is on your profile, on the API token page. Copy it.
  2. Make your own .env by copying the example file the starter project includes. Open the terminal with View › Terminal, then:
    Terminal · Mac
    cp .env.example .env
    Terminal · Windows
    copy .env.example .env
    Or do it in the Explorer: right-click .env.example, choose Copy, right-click an empty spot, choose Paste, and rename the copy to .env.
  3. Open .env. It starts as a copy of the example:
    .env.example
    COURTLISTENER_TOKEN=paste-your-token-here
    Replace paste-your-token-here with your token: no quotes, no spaces. Save.

Watch out

Never paste your token into the chat with the agent. Everything you type is sent to the model’s servers. In the Explorer, .env appears greyed out: that is VS Code showing that Git ignores it, so it will never be committed.

Write a tool: lookup.py

A tool, for an agent, can be an ordinary program. You’ll have the agent write a short Python program that calls CourtListener. “Only Python’s standard library” means nothing extra to install.

  1. Send this prompt. In Manual mode, Claude Code shows you the new file before creating it and asks before running any test command. Read each one before you approve.
    Prompt 6 · lookup.py
    Write lookup.py using only Python's standard library. It uses the CourtListener REST API v4 and reads the token from .env as COURTLISTENER_TOKEN. Never print the token.
Commands:
- python3 lookup.py verify <file>: send the file's text to CourtListener's citation lookup API and print a table: citation, found / not found, case name, link.
- python3 lookup.py verify-citation "<citation>": the same check for one citation.
- python3 lookup.py fetch "<citation>": find the case, download the text of its lead opinion, and save it as cases/[case-slug].txt. Begin the file with the case name, citation, court, date, and CourtListener link. Don't overwrite an existing file.
- python3 lookup.py cited-by "<citation>" [n]: list up to n (default 10) later opinions that cite this case, newest first: case name, court, date, citation, link.
- python3 lookup.py search "<query>": 5 matching opinions with case name, court, date, citation, link.
If a request fails or hits a rate limit, say so plainly and keep going.
  2. Try it yourself. In the terminal (on Windows, use py if python3 doesn’t work):
    Terminal
    python3 lookup.py verify-citation "5 U.S. 137"
python3 lookup.py verify-citation "5 U.S. 901"
python3 lookup.py verify-citation "Varghese v. China Southern Airlines Co., 925 F.3d 1339 (11th Cir. 2019)"

    The first should be found: Marbury. The second, your invented Henderson v. Pickering, should not. The third is one of the cases ChatGPT invented in Mata v. Avianca. If anything comes back as “found,” read the result closely: what case name did the database actually return? A citation that points to a different case is still a fake citation.

  3. Understand one line. Open lookup.py and pick any line that puzzles you.
    Prompt
    Explain line [number] of lookup.py three ways: to a 10-year-old, to a law student, and to an engineer.

Tip

Databases limit how often you can ask. CourtListener’s limits for a signed-in user are low: about 5 requests a minute (and 50 an hour, 125 a day). Check one case at a time, and if you hit a limit, wait a minute and try again.

Two things the web couldn’t do well

  1. Brief a case from its citation. No PDF needed: the workflow fetches the opinion from CourtListener into cases/, then briefs it.
    Prompt
    /brief Lindke v. Freed, 601 U.S. 187 (2024)

    A text file from CourtListener may not mark the official page numbers. If it doesn’t, the briefer should cite page numbers of the file instead, and say so. That’s the “never guess a page” rule at work.

  2. See who cites a case.
    Prompt
    Run python3 lookup.py cited-by "5 U.S. 137" 10 and summarize what the results do and don't tell us. Can we tell from them whether Marbury is still good law?

    The right answer is no. A list of citing cases isn’t a citator: it doesn’t say whether a later case followed, distinguished, or overruled this one. That’s what KeyCite and Shepard’s are for, and why your briefer’s Limitations section says later treatment was not researched.

Discuss

  1. Was the switch an improvement? What does the database check that the web didn’t, and what could the web catch that CourtListener can’t, such as a decision from last week?
  2. “Found” here means a case exists at that citation. What does it not tell you about whether the case supports the point the brief makes?
Why lookup.py can read .env when the agent can’t

Permission rules govern Claude Code’s tools: Read, Edit, and the shell commands it recognizes as reading or writing files. They don’t reach inside a program once it runs. When you approve python3 lookup.py …, Python opens .env by itself, and Claude Code never sees that file being opened.

Who tries to read .envWhat happensWhy
The agent’s Read toolBlockedThe Read(./.env) deny rule
The agent running cat .envBlockedClaude Code recognizes cat as reading a file and applies the same rule
python3 lookup.py …Reads itA program you approved opens the file itself; the rules check the command, not what the program does inside
You, in the editorReads itPermission rules limit the agent, not you

Here that gap is useful. The token goes straight from .env to CourtListener and never enters the conversation, so the model never sees it. That is why the prompt says “Never print the token”: anything the program prints lands in the agent’s context.

The same gap is also a risk. Any program the agent runs could read .env. So keep the defenses layered: read commands before approving them, keep the token out of chat and out of Git, and for real enforcement use OS-level sandboxing, where the operating system blocks the file for every program.

What a citation lookup request looks like

lookup.py doesn’t do anything magical. For verify-citation, it sends one web request to CourtListener’s citation lookup API (version 4) and reads the answer. Here is the same request written as a terminal command. You don’t need to run it; it’s here so you can see the parts.

Terminal · example request
curl -X POST "https://www.courtlistener.com/api/rest/v4/citation-lookup/" \
  --header 'Authorization: Token <your-token-here>' \
  --data 'text=Henderson v. Pickering, 5 U.S. 901 (1803)'
  • The endpoint is the address that ends in /citation-lookup/. POST means “here is some data for you to process.”
  • The header Authorization: Token … carries your token. The token is the only part that identifies you, which is why it stays in .env.
  • The data is a piece of text. CourtListener finds every citation in it, so you can send a whole paragraph, or a whole brief.

The answer comes back as JSON, a structured text format, with one entry per citation it found. Simplified, a not-found result looks like this:

Response · simplified
[
  {
    "citation": "5 U.S. 901",
    "status": 404,
    "clusters": []
  }
]
StatusMeaning
200Found: a case exists at that citation. clusters holds the matching case, including its name.
300More than one match (for example, several decisions on the same printed page).
400Looks like a citation, but the reporter isn’t one CourtListener knows.
404A valid-looking citation that isn’t in CourtListener.
429Too many: over the per-request limit or a rate limit. Wait and try again.

Source: CourtListener Citation Lookup API docs.

Notice what the lookup matches on: the volume, reporter and page, not the case name you typed. Even a 200 only tells you that some case lives at that citation, so a good checker also compares the name, and a good lawyer reads the case.
