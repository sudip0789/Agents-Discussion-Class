Skills, and how to vet them

Demo + discussion

Goal: see a popular skill at work, and learn to check a stranger’s skill before you install it.

A skill is a set of instructions someone else wrote for your agent. Once installed, your agent follows them with your access to your files. That makes installing a skill less like downloading a template and more like letting a stranger write part of your associate’s job description.

The demo

  1. Superpowers. Superpowers is a free, open-source skills library by Jesse Vincent for brainstorming, planning, testing, debugging and code review. We’ll open one of its skills on screen, brainstorming/SKILL.md. Notice what it is: a Markdown file of instructions. A short header gives its name and a description of when to use it; the rest is plain English telling the agent how to behave.

    Then we’ll run the brainstorming skill live. Watch what the agent does first: instead of starting to build, it asks what you actually want, and why.

  2. SkillSpector. SkillSpector is NVIDIA’s free, open-source scanner for agent skills. It reads a skill’s files, checks them against known risky patterns (hidden instructions, sending data to outside websites, reading secrets, dangerous code and more), and returns a risk score from 0 to 100 with a verdict:

    ScoreSeverityVerdict
    0–20LowSafe
    21–50MediumCaution
    51–80HighDo Not Install
    81–100CriticalDo Not Install

    Source: SkillSpector README (NVIDIA). See also NVIDIA’s guide, Scan agent skills before installation.

    Why bother? A 2026 academic study of about 31,000 public skills (Liu et al., “Agent Skills in the Wild”) found that 26.1% had at least one vulnerability and 5.2% showed high-severity patterns suggesting malicious intent. Those are warning signs flagged by automated analysis, not confirmed malware. The study is by university and industry researchers, not NVIDIA; SkillSpector’s README cites it.

  3. Predict, then scan. Before each scan, predict the verdict. We’ll scan Superpowers first, then a deliberately bad skill written for this class.

    For each report, ask: which findings would you have caught by reading the files yourself? Do any look like false alarms?

Watch out

The score helps you decide. It doesn’t replace reading the skill.

How to choose a skill

  • Start from a task you repeat, not from a list of popular skills.
  • Prefer known publishers and repositories that are actively maintained.
  • Read SKILL.md and any scripts before installing. If you can’t follow it, don’t install it.
  • Scan it with SkillSpector.
  • Install one at a time, in one project, and test it.

The full checklist, with red flags to look for, is in note N4.

Discuss

  1. A classmate shares a skill that “writes perfect case briefs.” What do you check before installing it?
  2. Which tasks in law school would you turn into a skill, and which would you never hand to one?
What’s inside a skill, and when the agent reads it

Skills follow an open format, Agent Skills, originally developed by Anthropic and now used by Claude Code, Codex and many other tools. A skill is a folder. The only required file is SKILL.md, which starts with a short header (the “frontmatter”) holding a name and a description. Everything after the header is instructions. The folder can also hold scripts and reference files.

Progressive disclosure

Anthropic calls this loading pattern progressive disclosure. In its words, “at startup, the agent pre-loads the name and description of every installed skill into its system prompt.” Only when a skill looks relevant does the agent read the full SKILL.md, and only if the instructions point to other files does it open those. That is why you can install many skills without filling the context window, and also why a vague description is a problem: the agent decides when to use a skill by reading that one line.

What this means for vetting

  • The body is the part that acts. A harmless-sounding description can sit on top of instructions that do something else entirely. Read past the header.
  • Scripts run with your access. A script in scripts/ is a real program. If the agent has Bash, it can run it.
  • Anthropic’s own advice: “We recommend installing skills only from trusted sources,” and auditing anything from a less-trusted source, including its bundled files and any instructions to connect to outside websites.
What the “Agent Skills in the Wild” study found

Liu and colleagues collected public skills from two skill marketplaces and analyzed them with a mix of pattern matching and AI-assisted classification. Their headline numbers:

FindingResult
Skills collected42,447
Skills analyzed31,132
At least one vulnerability26.1%
Data-exfiltration patterns (sending data out)13.3% of analyzed skills
Privilege-escalation patterns (reaching for more access)11.8% of analyzed skills
High-severity patterns suggesting malicious intent5.2%
Skills that bundle executable scripts, compared with instruction-only skills2.12 times as likely to be vulnerable (odds ratio)

Source: Yi Liu et al., “Agent Skills in the Wild: An Empirical Study of Security Vulnerabilities at Scale,” arXiv:2601.10338 (Jan. 2026).

Read these numbers the way you’d read any empirical claim:

  • It’s a preprint. arXiv papers are posted by their authors and haven’t necessarily been through peer review.
  • The detector isn’t perfect. The authors report 86.7% precision and 82.5% recall: some flagged skills are false alarms, and some real problems are missed. A scanner like SkillSpector has the same limits.
  • “Suggesting malicious intent” is not a finding of malice. It means the code or instructions matched high-severity patterns, such as sending data to an outside server. A human still has to look.

How SkillSpector turns findings into a score

Per its README, each finding adds points by severity: +50 for critical, +25 for high, +10 for medium, +5 for low, with a 1.3× multiplier if the skill includes executable scripts. So one critical finding in an instructions-only skill lands at 50, “Caution”; the same finding in a skill with scripts scores 65, “Do Not Install.” A low score means no known pattern matched, not that the skill is good.

Try it

After class, if you have Python 3.12+ and the uv installer, you can install SkillSpector and scan a skill folder. The --no-llm flag runs only the fast pattern checks, without sending the skill to an AI model for a second opinion.

Terminal
uv tool install git+https://github.com/NVIDIA/skillspector.git
skillspector scan ./my-skill/ --no-llm
