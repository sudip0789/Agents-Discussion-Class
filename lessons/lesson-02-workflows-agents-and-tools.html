Lesson 2 · Part 1: Foundations

Workflows, agents, and tools

Talk + polls

Goal: tell a workflow from an agent, and see how tools turn a model into something that acts.

A model on its own can only produce output: text, and for some models images or audio. Everything an agent does, from opening a PDF to searching the web, happens through tools. The two questions for this lesson: who decides the steps, and what is the agent allowed to touch?

Four pieces you’ll hear about

These words get used loosely. Here is how we’ll use them today, and where each one shows up in the agent you’ll build.

PieceWhat it isWho decides the stepsIn your project
WorkflowA fixed recipe of stepsYou, when you write itThe /brief skill: ask three questions, brief the case, check the brief
AgentA model plus tools plus a loop that runs until the task is doneThe agentClaude Code itself
SubagentA separate agent with its own instructions and toolsThe agent, within its toolscase-briefer and brief-checker
SkillInstructions an agent loads when relevant, or that you run by nameYou or the agent/brief is a skill

A legal analogy: a workflow is a closing checklist. Every step is written down in advance, and the order doesn’t change. An agent is a junior associate handed a research assignment: you set the goal, and they decide which sources to pull, what to read next, and when they’re done. A subagent is a second associate you bring in for one job, like cite-checking, with access to only what that job needs.

What is a tool?

A model can’t open a file or visit a website. It can only produce text. A tool is an action the app around the model knows how to perform, such as “read this file” or “search the web for this.” Using one takes three steps:

  1. The model asks. Instead of answering, it writes a structured request: use the Read tool on cases/marbury-v-madison.pdf.
  2. The app runs it. Claude Code (or Codex) checks whether that tool is allowed, asks you if the rules say to, and then does the work on your computer.
  3. The result comes back. The text of the file, or the search results, is added to the context window. The model reads it and decides what to do next.

Repeat those three steps until the job is done, and you have an agent. Think of a partner who can only send memos: the memo says “pull the file,” a paralegal pulls it, and the file lands on the partner’s desk for the next decision.

Why it matters

The model only asks; the app acts. That gap is where you get control. Because every action passes through the app, the app can refuse it, or stop and ask you first. That is what permissions are, and it’s why the next table matters.

The access ladder

Each level adds a capability and a risk. The tool names are Claude Code’s; Codex has equivalents.

LevelToolsCan doNew risk
1. Read onlyRead, Glob, GrepRead and find filesAlmost none
2. Write+ Write, EditCreate and change filesOverwrites your work
3. Run commands+ BashRun programs, move or delete filesAlmost anything on your machine
4. Internet+ WebSearch, WebFetchSearch and read web pagesUntrusted content, invented sources
5. Outside apps+ MCP tools (MCP is the Model Context Protocol, a standard way to plug outside services into an AI app)Email, calendar, databasesActs in your real account

The ladder is a way to think, not a rule that you must climb in order. You choose tools one by one. The case briefer you’ll build in lesson 7 gets Read, Glob, Write: it can read the opinion and save a brief, but it has no Bash, no Edit and no web. The checker you add in lesson 8 gets Read, Glob, WebSearch, WebFetch: it can look up cited cases online, but it can’t change any file. Every tool on those lines is a decision someone made.

One risk sits on every rung, even the first: whatever the agent reads goes into the context window, and the model runs on the AI company’s servers. Reading is low-risk for your files, but not automatically low-risk for confidentiality.

Discuss

  1. An agent will help you review a client’s documents. Which rung would you allow, and which single tool would you be most reluctant to add? Would your answer change if the documents were already public?
  2. For an agent, “the agent decides the steps” is the whole point. Is that acceptable for legal work? Where would you insist on a workflow, with steps you wrote, instead?
The agent loop, step by step

Anthropic’s widely cited essay “Building effective agents” draws the same line this lesson does, in one sentence each:

  • Workflows: “Workflows are systems where LLMs and tools are orchestrated through predefined code paths.”
  • Agents: “Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage.”

It describes agents as “typically just LLMs using tools based on environmental feedback in a loop.” At each step the agent gets “ground truth” from the environment: the actual contents of the file, the actual search results. It can pause for human feedback at checkpoints, and it stops when the task is done or when a stopping condition, like a maximum number of steps, kicks in.

Claude Code’s own documentation describes its loop as gather context → take action → verify results, repeated until the task is complete, and notes that you can interrupt at any point. The verify step is the one to watch: an agent that checks its own work against the environment (did the file save? does the link open?) is far more reliable than one that only reasons about it.

Where you fit in the loop

You can enter the loop in three places: when you set the goal, at a checkpoint when the app asks you to approve an action, and at the end, when you read what it produced. The permission mode you choose in lesson 6 decides how often the middle one happens.

The access ladder as a staircase

Picture the ladder as stairs. Each step up lets the agent do more, and makes the worst case worse. The labels above each step give the new capability (first line) and the new risk (second line).

Three things the staircase hides

  • Bash nearly contains the other steps. A program run from the command line can read, write, delete, and reach the internet. Giving an agent Bash is close to giving it everything below and above it.
  • The internet rung imports risk. Web pages and PDFs can contain hidden instructions aimed at AI readers. Reading untrusted text is how an agent gets talked into things. You’ll test this in lesson 9, by hiding an instruction inside a brief.
  • MCP is about whose account it is. An MCP server connects the agent to a real service (your email, your calendar, a firm database) using your login. Its actions are your actions.
